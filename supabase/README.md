# Включение синхронизации аккаунта (Supabase)

По умолчанию приложение хранит аккаунт только локально на устройстве
(AsyncStorage). Чтобы включить синхронизацию между устройствами, нужно
завести бесплатный проект на [supabase.com](https://supabase.com) — код
интеграции уже написан и переключится на него автоматически, как только
появятся ключи.

## Шаги

1. Создайте проект на supabase.com (Free tier достаточно).
2. Откройте **SQL Editor** и выполните `schema.sql` из этой папки — он
   создаёт таблицу `profiles`, политики доступа (RLS) и функцию проверки
   занятости имени пользователя.
3. Откройте **Authentication -> Providers -> Email** и **выключите**
   "Confirm email" — приложение использует технический email вида
   `username@animequiz.local`, подтвердить который невозможно.
4. Откройте **Project Settings -> API** и скопируйте:
   - **Project URL**
   - **anon / public key** (не `service_role` — это публичный ключ,
     безопасный для клиента)
5. Создайте файл `.env` в корне проекта (он в `.gitignore`, в репозиторий
   не попадёт):

   ```
   EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   ```

6. Перезапустите `expo start` — приложение подхватит переменные окружения
   и начнёт использовать Supabase вместо локального хранилища для новых
   регистраций и входов.

## Если проект уже создан раньше — новые миграции

Файл `schema.sql` со временем пополняется. Если у вас уже есть рабочий
проект, не запускайте файл целиком заново — выполните в **SQL Editor**
только те блоки из секции `-- MIGRATIONS` внизу файла, которых ещё нет
в вашей базе (каждый снабжён комментарием, что он делает; `create or
replace` / `if not exists` делают их безопасными для повторного запуска).
На момент написания там есть: колонка `daily_challenge`, view
`public.leaderboard` и функция `get_auth_email` (нужна для восстановления
пароля, см. ниже).

## Восстановление пароля

Приложение позволяет указать реальный email при регистрации специально
для сброса пароля (поле необязательное — без него используется технический
`username@animequiz.local`, для которого письмо прислать некому). Чтобы
ссылка из письма действительно открывала приложение и подставляла токены:

1. Выполните миграцию `get_auth_email` из `schema.sql` (см. выше), если
   ещё не выполняли — без неё вход по имени пользователя продолжит
   работать, но `resetPasswordForEmail` не найдёт нужный email.
2. Откройте **Authentication -> URL Configuration** и добавьте в
   **Redirect URLs** адрес `animequiz://reset-password` — без этого
   Supabase отклонит ссылку восстановления как непредусмотренную.
   Для веб-сборки дополнительно добавьте тот HTTPS-адрес, на котором она
   размещена (например `https://ваш-домен/reset-password`).
3. Готово — экран "Забыли пароль?" на экране входа отправит письмо, а
   переход по ссылке из письма откроет приложение на экране задания
   нового пароля.

## Как это работает

- Логин/пароль реализованы через Supabase Auth (email+password), где
  email синтезируется из имени пользователя — пользователю ввод почты
  не нужен.
- Профиль (аватар, статистика, серия дней, избранный персонаж) хранится
  в таблице `profiles`, привязанной к `auth.users` через `id`.
- Запись профиля применяется локально сразу (оптимистично) и в фоне
  отправляется в Supabase — если сети нет, следующая успешная запись
  всё равно донесёт актуальное состояние.
- Realtime-подписка на строку профиля обновляет экран, если тот же
  аккаунт что-то изменил на другом устройстве.
- Без `.env` (или без выполненного `schema.sql`) приложение продолжает
  работать как раньше — полностью локально, без каких-либо изменений
  в поведении.
