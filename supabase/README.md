# Включение синхронизации аккаунта (Supabase)

По умолчанию приложение хранит аккаунт только локально на устройстве
(AsyncStorage). Чтобы включить синхронизацию между устройствами, нужно
завести бесплатный проект на [supabase.com](https://supabase.com) — код
интеграции уже написан и переключится на него автоматически, как только
появятся ключи.

## Шаги

1. Создайте проект на supabase.com (Free tier достаточно).
2. Откройте **SQL Editor** и выполните `schema.sql` из этой папки — он
   создаёт таблицу `profiles`, политики доступа (RLS) и функцию проверки
   занятости имени пользователя.
3. Разверните Edge Function `auth-helper` (папка `supabase/functions/`
   в этом репозитории) — **обязательный шаг**, без него не работают ни вход
   по паролю, ни восстановление пароля (см. «Зачем нужна Edge Function»
   ниже):

   ```
   npm install -g supabase
   supabase login
   supabase link --project-ref <ваш-project-ref>   # из Project Settings -> General
   supabase functions deploy auth-helper
   ```

   Никаких секретов настраивать не нужно — `SUPABASE_URL`,
   `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` Supabase передаёт в
   функцию автоматически.
4. Откройте **Authentication -> Providers -> Email** и **выключите**
   "Confirm email" — приложение использует технический email вида
   `username@animequiz.local`, подтвердить который невозможно.
5. Откройте **Project Settings -> API** и скопируйте:
   - **Project URL**
   - **anon / public key** (не `service_role` — это публичный ключ,
     безопасный для клиента)
6. Создайте файл `.env` в корне проекта (он в `.gitignore`, в репозиторий
   не попадёт):

   ```
   EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
   ```

7. Перезапустите `expo start` — приложение подхватит переменные окружения
   и начнёт использовать Supabase вместо локального хранилища для новых
   регистраций и входов.

## Зачем нужна Edge Function

Вход по имени пользователя и восстановление пароля должны превратить
«имя пользователя» в конкретный Supabase Auth email — но этот email может
быть настоящим адресом, который игрок указал при регистрации специально
для восстановления пароля (см. ниже), а не только техническим
`username@animequiz.local`. Раньше это делал SQL-RPC, вызываемый прямо с
клиента и доступный анонимно — а значит, **любой** мог получить email
любого игрока по одному только имени пользователя (найденная при
аудите уязвимость раскрытия персональных данных). Теперь это делает
Edge Function (`supabase/functions/auth-helper`) с доступом через
`service_role` — она сама ищет нужный email и сама же выполняет вход или
запрос сброса пароля внутри себя, так что email никогда не попадает в
клиентское приложение.

## Если проект уже создан раньше — новые миграции

Файл `schema.sql` со временем пополняется. Если у вас уже есть рабочий
проект, не запускайте файл целиком заново — выполните в **SQL Editor**
только те блоки из секции `-- MIGRATIONS` внизу файла, которых ещё нет
в вашей базе (каждый снабжён комментарием, что он делает; `create or
replace` / `if not exists` / `drop ... if exists` делают их безопасными
для повторного запуска). На момент написания там есть: колонка
`daily_challenge`, таблица `public.friendships` (нужна для экрана
«Друзья», см. ниже), view `public.leaderboard` (расширенный — теперь
включает `id`, `streak`, `achievements`, `stats`, `total_games` в
дополнение к тому, что уже было), и — если вы разворачивали более
раннюю версию этого проекта — удаление функции `get_auth_email` (замена
которой на Edge Function описана выше; выполните и разверните
`auth-helper`, если ещё не делали).

## Друзья

Экран «Друзья» (поиск игроков, заявки в друзья, сравнение, вызов на
битву) работает через таблицу `public.friendships` — выполните её
миграцию из `schema.sql`, если ещё не делали. Уровень и XP на этом
экране не хранятся отдельно — считаются на лету из тех же очков за
верные ответы, что уже есть в `profiles.stats`, а название уровня берёт
названия сложностей категорий (Новичок…Легенда). Кнопка «Написать» пока
не открывает переписку — сообщения друзьям в разработке; кнопка «Бросить
вызов» создаёт комнату «Битвы фанатов» и открывает системное окно
«Поделиться», чтобы отправить код другу любым способом — прямой
доставки вызова прямо в приложении друга пока нет.

## Восстановление пароля

Приложение позволяет указать реальный email при регистрации специально
для сброса пароля (поле необязательное — без него используется технический
`username@animequiz.local`, для которого письмо прислать некому). Чтобы
ссылка из письма действительно открывала приложение и подставляла токены:

1. Убедитесь, что Edge Function `auth-helper` развёрнута (см. выше) — без
   неё запрос на сброс пароля не сможет найти нужный email.
2. Откройте **Authentication -> URL Configuration** и добавьте в
   **Redirect URLs** адрес `animequiz://` — без этого Supabase отклонит
   ссылку восстановления как непредусмотренную. Для веб-сборки
   дополнительно добавьте тот HTTPS-адрес, на котором она размещена, без
   пути (например `https://ваш-домен` — у сборки нет серверной
   маршрутизации, поэтому редирект должен указывать точно на корень).
3. Готово — экран "Забыли пароль?" на экране входа отправит письмо, а
   переход по ссылке из письма откроет приложение на экране задания
   нового пароля.

Тот же адрес (`animequiz://` / корень веб-адреса) используется и для входа
через Google — см. ниже, добавлять его в Redirect URLs нужно только один
раз.

## Вход через Google

Кнопка "Войти через Google" показывается только когда настроен Supabase
(локальный режим для входа по паролю сторонних провайдеров не имеет).
Понадобится:

1. В [Google Cloud Console](https://console.cloud.google.com/apis/credentials)
   создайте **OAuth client ID** типа **Web application**. В **Authorized
   redirect URIs** укажите адрес обратного вызова Supabase — он показан
   на шаге 2 ниже (`https://<project-ref>.supabase.co/auth/v1/callback`).
   Сохраните **Client ID** и **Client Secret**.
2. В Supabase откройте **Authentication -> Providers -> Google**,
   включите провайдер и вставьте туда Client ID и Client Secret из
   предыдущего шага.
3. Убедитесь, что `animequiz://` (и HTTPS-корень веб-сборки) добавлены в
   **Authentication -> URL Configuration -> Redirect URLs** — тот же
   адрес, что и для восстановления пароля выше.
4. Готово — при нажатии на "Войти через Google" на вебе произойдёт обычный
   переход на страницу Google и обратно, а в нативной сборке откроется
   окно входа поверх приложения (`expo-web-browser`). Если для аккаунта
   ещё нет профиля в `profiles`, он будет создан автоматически при первом
   входе (имя пользователя подбирается из email и, если оно уже занято,
   дополняется случайными цифрами — сменить его потом можно как обычно).

## Уведомления, чат и сезонный рейтинг

Три новые таблицы из `schema.sql` (миграции внизу файла):

- `public.battle_invites` — вызов на битву, отправленный с профиля друга,
  долетает до цели даже если она не смотрит на экран «Битва» в этот момент.
  Добавлена в `supabase_realtime`, как и `public.friendships` — на неё и
  на новые заявки в друзья подписывается экран «Друзья», показывая баннер
  и локальное уведомление (через `expo-notifications`, без сервера push —
  сработает, пока приложение открыто в фоне на устройстве).
- `public.messages` — переписка между друзьями (только текст, без групп и
  вложений). Кнопка «Написать» в профиле друга теперь открывает реальный
  чат.
- `public.round_results` — лог каждого сыгранного раунда, нужен только для
  того, чтобы посчитать рейтинг за неделю/сезон (обычные `profiles.stats`
  хранят только накопленный итог, из него нельзя выделить период задним
  числом). На основе неё — `public.leaderboard_weekly` и
  `public.leaderboard_season` (сезон = календарный месяц) — такие же
  безопасные представления без доступа к сырым строкам.

Если у вас уже развёрнут проект, выполните эти три блока миграций в
**SQL Editor** — они идут одним `ALTER PUBLICATION ... ADD TABLE`, если
`friendships` уже была добавлена в publication раньше, повторный запуск
вернёт ошибку "already member of publication" — в этом случае просто
пропустите эту строку и выполните остальное.

## Как это работает

- Логин/пароль реализованы через Supabase Auth (email+password), где
  email синтезируется из имени пользователя — пользователю ввод почты
  не нужен. Само превращение имени пользователя в email происходит
  внутри Edge Function `auth-helper`, а не на клиенте (см. выше).
- Профиль (аватар, статистика, серия дней, избранный персонаж) хранится
  в таблице `profiles`, привязанной к `auth.users` через `id`.
- Запись профиля применяется локально сразу (оптимистично) и в фоне
  отправляется в Supabase — если сети нет, следующая успешная запись
  всё равно донесёт актуальное состояние.
- Realtime-подписка на строку профиля обновляет экран, если тот же
  аккаунт что-то изменил на другом устройстве.
- Без `.env` (или без выполненного `schema.sql`) приложение продолжает
  работать как раньше — полностью локально, без каких-либо изменений
  в поведении.

## Чат: ответы, реакции, удаление

Внизу `schema.sql` есть блок с расширением чата — выполните его в
**SQL Editor**, если проект уже развёрнут:

- `messages.reply_to_id` — на какое сообщение отвечает это (`on delete set
  null`: если процитированное сообщение удалили, сам ответ остаётся, просто
  без цитаты).
- `public.message_reactions` — по одной реакции на человека на сообщение
  (уникальное ограничение на пару `message_id + user_id`; повторный тап по
  той же эмодзи её снимает, другая — заменяет). Видны только двум участникам
  переписки — политика проверяет доступ через саму таблицу `messages`.
- Политика удаления на `messages` — удалять можно только свои сообщения.
- `alter table public.messages replica identity full` — без этого Realtime в
  событии `DELETE` присылает только первичный ключ, и RLS не может понять,
  кому это событие показывать: собеседник просто не узнал бы, что сообщение
  удалили.

## Аватары

Аватар — это картинка, которую игрок выбирает сам: либо своя из галереи
телефона, либо одна из готовых, которые лежат прямо в приложении
(`assets/avatars/`). Пока ничего не выбрано, показывается первая буква
имени. Раньше приложение рисовало аватар само по случайным чертам лица —
такие остались только у 54 персонажей квиза. Рамки, которые открываются
по уровню, остались; узоры фона убраны.

Свои картинки хранятся в Supabase Storage — выполните блок «Avatars»
внизу `schema.sql`, он создаёт всё, что нужно:

- бакет `avatars`, публичный на чтение (аватар виден в чате, у друзей и в
  рейтинге, в том числе до входа) и с лимитом 1 МБ на файл;
- политики на `storage.objects`: писать и удалять можно только внутри
  папки, названной своим `auth.uid()`, так что чужую картинку не
  перезаписать.

Блок можно выполнить отдельно от остального файла — редактор Supabase
прогоняет вставленное одной транзакцией, так что удобнее скопировать
только его. Если на политиках для `storage.objects` вернётся ошибка прав,
те же три правила («писать/менять/удалять только в папке своего
`auth.uid()`») можно создать мышкой в **Storage -> Policies**.

Приложение обрезает выбранную картинку по центру в квадрат, ужимает до
224x224 JPEG (~10–14 КБ) и кладёт в `avatars/<user-id>/avatar-<время>.jpg`,
а в `profiles.avatar.photoUri` пишет публичную ссылку — так страница
рейтинга тянет пятьдесят коротких строк, а не пятьдесят картинок. Старый
файл удаляется при следующей загрузке. Имя файла со временем нужно из-за
CDN: по одному и тому же пути отдавалась бы закешированная старая
картинка.

Если Supabase не подключён (полностью локальный режим) или загрузка не
удалась, картинка просто сохраняется внутрь самого JSON профиля как
`data:`-URI — аватар всё равно появится. Код отрисовки принимает любой
URI, так что оба варианта работают одинаково.

Готовые аватарки в Storage не попадают: в профиле хранится только их
идентификатор (`avatar.presetId`), а картинка берётся из сборки.

## Групповые чаты

Кнопка «Группы» в шапке экрана друзей открывает список групп, там же
создаётся новая: название плюс отметки на друзьях. Внутри — тот же чат,
что и в личке (свайп-ответ, реакции, удаление своих сообщений), только
над чужими сообщениями подписано, кто их написал, а по шапке открывается
состав группы с кнопкой «Выйти».

Блок «Group chats» внизу `schema.sql` создаёт четыре таблицы —
`chat_groups`, `chat_group_members`, `group_messages`,
`group_message_reactions` — и их политики. Отдельные таблицы, а не
`group_id` в существующей `messages`: личное сообщение адресовано
человеку, а групповое — комнате, и смешивать их в одной строке значит
усложнить каждую политику на ней.

Главная тонкость — функция `public.is_group_member(gid, uid)` с
`security definer`. Проверять членство надо изнутри политик самой
таблицы членства, а это бесконечная рекурсия; функция читает таблицу
в обход RLS и разрывает цикл. Она отвечает ровно на один вопрос «да/нет»
и никаких строк наружу не отдаёт, а `execute` выдан только роли
`authenticated`.

Вторая тонкость, на которой это сломалось в первой версии: группа
создаётся раньше, чем в ней появляется хоть один участник — включая
создателя. Поэтому в политике на `select` для `chat_groups` есть
`owner_id = auth.uid()` рядом с проверкой членства. Без него
`insert ... returning` при создании группы не может прочитать строку,
которую только что вставил, и создание падает.

Кто что может: видеть группу и её переписку — участники и создатель;
добавлять людей — только создатель; выйти — любой сам, удалить
кого-то — создатель; удалить своё сообщение — автор. Все три таблицы
добавлены в `supabase_realtime`, а `group_messages` получила
`replica identity full` — иначе событие `DELETE` не донесёт до
собеседников, что сообщение удалили.

## Рейтинг: карточка игрока и статус «в сети»

Нажатие на строку в глобальном рейтинге открывает карточку с кнопками
«Написать», «Добавить в друзья» и «Бросить вызов» — переиспользует тот же
API, что и экран друзей, отдельных таблиц не требует.

Статус «в сети» не хранится в базе — это отдельный Supabase Realtime
presence-канал (`presence:online-players`), на который клиент подписывается,
пока профиль загружен, и «трекает» себя. Ничего разворачивать не нужно:
Realtime уже включён для остальных функций (чат, друзья), presence работает
поверх того же соединения.
